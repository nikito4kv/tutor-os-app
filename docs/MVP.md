# MVP — скоуп

## Walking skeleton (обязан работать end-to-end)

Единственный сквозной сценарий — хребет MVP. Всё остальное вокруг него.

1. Репетитор регистрируется и входит.
2. Добавляет ученика (карточка).
3. Заводит пакет занятий (например, 8) → появляется баланс занятий.
4. Создаёт урок в расписании.
5. Проводит урок (на первом этапе — без видео).
6. Жмёт **«Завершить урок»** → срабатывает автоматизация:
   - списывается 1 занятие с баланса,
   - урок уходит в историю,
   - сохраняется тема/короткая заметка,
   - если занятий мало — подсветить «пора пополнить».
7. Выдаёт домашку.
8. Ученик по своей ссылке (без регистрации) видит расписание, баланс, домашку;
   отмечает «сдано» (текст/файл).
9. Репетитор отмечает ДЗ «проверено» с комментарием.

**«Завершить урок»** как триггер цепочки — ключевая механика. Делаем её надёжной,
но простой: **синхронно, в одном месте**, без очередей и фоновых воркеров.
Реализация — функция БД `complete_lesson` (см. `docs/ARCHITECTURE.md`).

## Must-have (тонко)

- Регистрация/вход репетитора. ✅ (реализовано)
- Карточка ученика (CRUD) + список. ✅ (реализовано — эталонная зона)
- Пакеты занятий + баланс + ручной учёт оплат. ✅ (реализовано — срез 3)
- Расписание: создать урок, неделя/список, статусы (+ отмена). ✅ (реализовано — срез 4)
- Завершение урока с автоматизацией. ✅ (реализовано — срез 5)
- Заметки и история уроков в карточке. ✅ (реализовано — срез 5)
- Домашка: выдал → сдал (по ссылке) → проверил с комментарием. ✅ (реализовано — срезы 6–7)
- Ссылка ученика без регистрации (расписание, баланс, ДЗ + сдача ДЗ). ✅ (реализовано — срез 7)
- Простейшие email-уведомления (Resend) — или замокать и включить позже. ⏳
- Telegram-уведомления (репетитор + ученик) — срез 11 (см. ADR-0005). ✅

## Видео-урок — отдельный тонкий срез (срез 8, отложен)

Комната «видео + доска» — отличие от Zoom и самый тяжёлый кусок. Делается
**последним**, только готовыми сервисами: видео — **Daily.co** (prebuilt iframe),
доска — **tldraw**. Свой WebRTC не пишем. Ученик входит по той же ссылке.
**Решение по срокам (1–2 недели до первого теста): срез 8 отложен** — первый тест
проверяет учётное ядро (срезы 1–7).

## Явно НЕ в этом билде

CRM/воронка лидов · портал родителя с аналитикой · дашборды (доход/отток/retention) ·
все AI-функции · мини-школа и сложные роли · онлайн-приём платежей и webhook ·
WhatsApp-уведомления · библиотека материалов · запись урока ·
drag-перенос в сетке недели · возвраты · групповые пакеты.

Модель данных заложена так, чтобы это можно было добавить позже — но не сейчас.

**Повторяющиеся уроки — теперь в скоупе** (срез 9). Реализация тонкая и
материализованная: правило RFC 5545 (RRULE) хранится на серии `lesson_series`,
а сами уроки остаются обычными строками `lesson` (через `series_id`) — поэтому
завершение, баланс, RLS и привязка ДЗ работают без изменений. Повтор обязан быть
ограничен (`COUNT`/`UNTIL`), генерация — синхронная, без фоновых воркеров.
Мультивыбор дней недели и продление горизонта — в бэклоге.

## Порядок сборки (тонкие срезы)

| Срез | Зона                                                                                                                                               | Статус      |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| 1    | Фундамент: Next + Supabase + auth + RLS + каркас                                                                                                   | ✅ готово   |
| 2    | Ученики: CRUD + список + карточка с вкладками                                                                                                      | ✅ готово   |
| 3    | Деньги: пакеты + баланс + ручные оплаты                                                                                                            | ✅ готово   |
| 4    | Расписание: создать урок, неделя/список, статусы                                                                                                   | ✅ готово   |
| 5    | Завершение урока: автоматизация + история                                                                                                          | ✅ готово   |
| 6    | Домашка: выдал → сдал → проверил, Storage                                                                                                          | ✅ готово   |
| 7    | Ссылка ученика: сдача ДЗ (read-only уже есть)                                                                                                      | ✅ готово   |
| 8    | Комната урока (Daily + tldraw)                                                                                                                     | 🔵 отложено |
| 9    | Флоу урока: модалка-карточка, завершение с темой/ДЗ, перенос, RRULE-повторы, дедлайн ДЗ, «не пришёл»                                               | ✅ готово   |
| 10   | Роль администратора (служебная, вне продуктового MVP): инбокс обратной связи + общие цифры (миграция `0012`)                                       | ✅ готово   |
| 11   | Telegram-уведомления: привязка репетитора/ученика, событийные + отложенные (миграция `0014`, ADR-0005)                                             | ✅ готово   |
| 12   | Внутренний чат: диалоги преподавателя с учениками, файлы до 10 МБ, вкладка в карточке и блок на публичной ссылке (миграции `0015`, `0016`, `0017`) | ✅ готово   |

Срезы 1–7 = учётное ядро (тестируемо без видео). Срез 8 = отличие от Zoom.
Срез 9 = довод флоу урока до рабочего инструмента (миграции `0003`, `0004`).

**Срез 10 — служебный, не часть продуктового MVP.** Внутренний аккаунт
разработчиков: читает обращения из кнопки «Поддержка» (раньше собирались, но негде
было читать), показывает общие счётчики (репетиторы/ученики/уроки/новые обращения)
и read-only списки репетиторов/учеников для поддержки. Деньги и продуктовая
аналитика (доход/отток/retention) по-прежнему **вне скоупа** — здесь только
агрегаты, инбокс и узкие справочники через admin RPC. Детали: ADR-0003,
ADR-0004 и `docs/specs/admin-role/`.
