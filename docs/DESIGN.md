# DESIGN — система дизайна tutorOS

Это **закон по дизайну**. Любая новая страница, окно, компонент или состояние
строится по этим правилам. Сомневаешься — делай как здесь, не изобретай свой стиль.
Дополняет правила проекта (про стили) — не противоречит им.

Эталон вживую — зона `src/features/students` и карточка ученика
(`src/app/(app)/students/[id]/page.tsx`).

---

## 1. Принципы

- **Токены — единственный источник правды по цвету.** Никаких сырых hex и палитр
  Tailwind (`emerald-*`, `amber-*`, `slate-*`, `#0F172A`) в компонентах. Только
  семантические токены: `bg-primary`, `text-muted-foreground`, `border-input`, …
- **Только Tailwind + shadcn/ui.** Примитивы живут в `src/components/ui`. Не тянем
  сторонние UI-киты. **Исключения (разрешены явно):** `react-day-picker` (движок
  shadcn-компонента `Calendar`, стилизуется нашими токенами через `classNames`),
  `date-fns` (его peer + наша дата-логика), `rrule` (правила повторяющихся уроков,
  только в серверном `features/lessons/recurrence.ts`) и `motion` (`motion/react`) —
  анимационный движок для клиентских leaf-компонентов (скролл-reveal, жесты), см. §11
  и ADR-0006. Это не UI-кит — добавлять другие визуальные библиотеки по-прежнему нельзя.
- **Бизнес-логика не в компонентах.** Компонент рисует; данные/мутации — в
  `features/<зона>/queries.ts` и `actions.ts`.
- **Тексты — только через `t.*`** (`src/lib/i18n`). Хардкод-строк в JSX нет.
- **Состояния обязательны:** у каждого списка/экрана есть `loading`, `empty`, `error`
  (см. §8).
- **Иконки — только `lucide-react`** (SVG), фиксированный размер `size-4/5/6`.
  Эмодзи как иконки — запрещены.

---

## 2. Токены и палитра

Бренд (teal) и вся палитра заданы **один раз** как CSS-переменные в
`src/app/globals.css` — `:root` (светлая) и `.dark` (тёмная). Tailwind мапит их в
`tailwind.config.ts`. Сменить бренд = поменять `--primary` в одном месте.

| Токен                            | Назначение                                         |
| -------------------------------- | -------------------------------------------------- |
| `background` / `foreground`      | фон страницы / основной текст                      |
| `card` / `card-foreground`       | поверхности карточек                               |
| `primary` / `primary-foreground` | бренд-акцент, основные кнопки                      |
| `secondary` / `muted`            | приглушённые поверхности и текст                   |
| `accent` / `accent-foreground`   | активные/наведённые состояния                      |
| `destructive`                    | удаление, ошибки                                   |
| `success`                        | успех, подтверждение, проверенное ДЗ               |
| `warning`                        | предупреждение, низкий баланс, средняя сила пароля |
| `border` / `input` / `ring`      | границы, поля ввода, кольцо фокуса                 |

**Паттерн мягкой заливки.** Для «тихих» плашек (бейджи, блоки сообщений) не заводи
новых токенов — используй прозрачность:

```tsx
// ошибка
className = "bg-destructive/10 text-destructive";
// успех (фидбэк, сообщение об отправке)
className = "bg-success/10 text-success";
// бейдж-предупреждение
className = "bg-warning/15 text-warning";
```

Базовые значения `--success`/`--warning`/`--destructive` подобраны текстобезопасными
(≥4.5:1 на фоне), поэтому `text-success` читается и на белом, и на тинте.

> ⛔️ Если добавляешь новый смысловой цвет — заведи токен (`:root` **и** `.dark`),
> прокинь в `tailwind.config.ts`, и только потом используй. Сырой цвет в компоненте
> не пройдёт ревью.

## 3. Типографика

- **Шрифт — Manrope** (кириллица), подключён один раз в `src/app/layout.tsx` как
  `--font-sans` и проброшен в `font-sans`. Отдельные `next/font` по зонам не заводим.
- **Шкала (ориентир):** h1 — `text-2xl font-semibold` (лендинг-hero — до `text-5xl
font-bold`); h2 — `text-lg font-semibold`; тело — `text-sm`/`text-base`; вспомогательное
  — `text-xs text-muted-foreground`.
- **Высота строки** тела — 1.5–1.75 (`leading-relaxed` для длинных абзацев).
- **Длина строки** — 65–75 символов. Длинные текстовые блоки ограничивай по ширине
  (`max-w-prose` / `max-w-2xl`), не давай растекаться на всю ширину контейнера.

---

## 4. Layout и пространство

- **Контейнер** — `container` (центр, padding 1.5rem, max 1400px на 2xl). Внутри
  приложения контент уже обёрнут в `(app)/layout.tsx`.
- **Сетки** — мобайл-ферст: `grid gap-4 sm:grid-cols-2 lg:grid-cols-3`. Один
  `max-w-*` на странице, не мешай разные.
- **Вертикальные ритмы** — `space-y-6` между секциями экрана, `space-y-3`/`space-y-4`
  внутри секции.
- **Шкала z-index:** контент `0` → залипающие шапки `30` → оверлеи/диалоги `50`.
  Не выдумывай промежуточные значения.

---

## 5. Компоненты-примитивы

Берём из `src/components/ui`. Варианты заданы через `cva` — не переопределяй цвета
классами по месту.

- **Button** — варианты `default | destructive | outline | secondary | ghost | link`;
  размеры `default | sm | lg | icon`. Кольцо фокуса встроено. Иконка-кнопка обязана
  иметь `aria-label`.
- **Input / Textarea** — встроены focus-ring и `aria-[invalid]`-стили. Всегда с
  `<Label htmlFor>`.
- **Badge** — `default | secondary | outline | success | warning | destructive`.
- **Card** — стандартная поверхность (`bg-card`). Карточка-ссылка: оборачивай в
  `<Link>` и давай `hover:border-primary transition-colors` (без сдвига layout).
- **Dialog** — модалка на Radix (focus-trap, ESC, scroll-lock из коробки). См. §7.

Ссылки, которые НЕ являются `Button`, но кликабельны (nav, табы, якоря) — добавляй
общий `focusRing` из `src/lib/styles.ts`.

## 6. Паттерны страниц

- **Шапка экрана:** слева `h1`, справа основное действие.
  ```tsx
  <div className="flex items-center justify-between">
    <h1 className="text-2xl font-semibold">{t.students.title}</h1>
    <Link href="…" className={buttonVariants()}>
      <Plus className="size-4" />…
    </Link>
  </div>
  ```
- **Списки-коллекции:** либо сетка карточек-ссылок, либо
  `ul.divide-y.rounded-md.border` с `li` в `flex items-center justify-between`.
- **Табы:** ссылки с `?tab=`, активная — `border-primary text-foreground`. Контейнер
  обязан иметь `overflow-x-auto`, элементы — `whitespace-nowrap` (узкие экраны).
- **Формы создания/редактирования:** короткая модалка через `FormDialog`
  (`src/components/form-dialog.tsx`) — кнопка-триггер открывает `Dialog` с блюром
  фона, как `AddPackage`/`AddLesson`/`CreateStudentDialog`. Это **дефолт** для
  добавления ученика/урока/ДЗ/оплаты/пакета (см. §7).

## 7. Всплывающие окна (выбор паттерна)

Решение зафиксировано в **ADR-0002**. Сначала выбери уровень, потом строй:

1. **Модалка (`Dialog` / `FormDialog`)** — **основной способ** добавления и
   редактирования: ученик, урок, ДЗ, оплата, пакет. Короткая форма (≈2–6 полей)
   открывается поверх контента с блюром фона — список под ней не «прыгает».
   Модалка же — для **подтверждения деструктива**, мелкого выбора и предпросмотра.
   Форму оборачивай в `FormDialog` (`src/components/form-dialog.tsx`), а не собирай
   `Dialog` вручную.
2. **Отдельная страница/маршрут** — только для крупной самостоятельной формы со
   своим URL (мастер из нескольких шагов, длинный профиль). В MVP таких нет.
3. **Инлайн-форма со сворачиванием** — **больше не используем** для создания: она
   двигает layout. Допустима только если форма логически часть строки списка
   (редактирование значения на месте).

**Обязательные правила модалки** (всё уже есть в `components/ui/dialog.tsx` и
`FormDialog`):

- Заголовок `DialogTitle` (для screen-reader); при необходимости — `DialogDescription`.
- Focus-trap, закрытие по `Esc` и клику по оверлею, scroll-lock — из Radix, не отключай.
- Оверлей `bg-background/80 backdrop-blur-sm` (через токен; следует теме — тёмный
  скрим в тёмной теме, светлый в светлой, не сырой чёрный).
- Контент скроллится на узких экранах (`max-h-[90vh] overflow-y-auto` — в примитиве).
- Кнопки — в `DialogFooter`, основное действие **справа**, отмена слева через `DialogClose`.
- Кнопка-крестик с `sr-only`-подписью (`t.common.close`).
- Контент на токенах (`bg-card`), не белый хардкодом — чтобы работало в тёмной теме.
- Анимации с `motion-reduce:animate-none`.

## 8. Состояния

Каждый список/экран обязан покрывать три состояния:

- **loading** — `loading.tsx` со `Skeleton`-блоками (резервируй высоту, чтобы контент
  не «прыгал»).
- **empty** — `<EmptyState>` (`src/components/states`): иконка + заголовок +
  опциональное действие.
- **error** — `error.tsx` / `<ErrorState>` с кнопкой «Повторить».

---

## 9. Доступность (a11y) — обязательно

- **Фокус виден везде.** На ссылках/табах/якорях — `focusRing` из `lib/styles.ts`; в
  Button/Input уже встроен. Никогда не убирай outline без замены.
- **Контраст** — текст ≥ 4.5:1. Цвет не единственный носитель смысла (дублируй
  иконкой/текстом — как статусы уроков/ДЗ).
- **Тач-цели** ≥ 44×44px на мобильном.
- **Иконки-кнопки** — всегда `aria-label` (через `t.*`).
- **Формы** — `<Label htmlFor>` у каждого поля; ошибка рядом с полем
  (`role="alert"`), `aria-invalid` на инпуте.
- **Клавиатура** — порядок Tab совпадает с визуальным; всё интерактивное достижимо.
- **prefers-reduced-motion** — учтён глобально в `globals.css`; для точечной анимации
  используй вариант `motion-reduce:`.

## 10. Тёмная тема

- Управляется `next-themes` (class-стратегия). Провайдер — `src/components/theme-provider.tsx`
  в root layout (`attribute="class"`, `defaultTheme="system"`). Переключатель —
  `src/components/theme-toggle.tsx` (в sidebar и на лендинге).
- Тёмные значения **всех** токенов лежат в блоке `.dark` в `globals.css`. Новый токен
  → добавь его и туда.
- **Правило:** любую новую поверхность проверяй в обоих режимах. Если используешь
  токены (а не сырые цвета), тёмная тема работает сама.

## 11. Анимация

- Микровзаимодействия — **150–300ms**, `transition-colors`/`transition-transform`.
- Анимируй только `transform`/`opacity` (не `width`/`height`/`top`).
- Hover не должен сдвигать layout (меняй цвет/тень/границу, не размер).
- Всегда учитывай `motion-reduce:` (CSS) / `useReducedMotion()` (Motion).
- **Кривая по умолчанию** — strong ease-out `cubic-bezier(0.23, 1, 0.32, 1)` (она же
  в `revealUp`/`pressable` из `src/lib/styles.ts`). Один «голос движения».
- **CSS — по умолчанию.** Hover/active, микровзаимодействия и появление «на загрузке»
  делаем на Tailwind/`tailwindcss-animate` (`revealUp`, `pressable`): CSS идёт вне
  основного потока и не зависит от JS — для предопределённого движения это правильный
  инструмент.
- **Motion (`motion/react`) — точечно**, когда CSS не покрывает: появление по скроллу
  (`whileInView`, `viewport={{ once: true }}`), прерываемые жесты, пружины. Только в
  `"use client"` leaf-компонентах; общий примитив — `src/features/landing/reveal.tsx`.
  Обязателен `useReducedMotion()`. См. ADR-0006.
- **GSAP** разрешён законом для сложной скролл-хореографии (pin/scrub), но берём его
  лишь когда это действительно нужно — не как дефолт.
