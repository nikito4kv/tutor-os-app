# ADR-0002: Модалки для форм создания/редактирования

- **Статус:** принято
- **Дата:** 2026-06-11
- **Решают:** владелец продукта, команда

## Контекст

Формы добавления (пакет, оплата, урок, ДЗ) были **инлайн со сворачиванием**: кнопка
заменялась на `<form>` прямо в потоке страницы. При открытии форма вставлялась в
DOM и сдвигала весь контент ниже (списки, история) — классический content-jumping,
который раздражал на длинных вкладках карточки. Добавление и редактирование ученика
жили **на отдельных маршрутах** (`/students/new`, `/students/[id]/edit`), то есть
уводили со страницы. Пять входов ощущались как три разных механики.

Прежний `docs/DESIGN.md §7` предписывал инлайн как основной способ ввода, а модалки
запрещал для форм создания/редактирования. Меняем это правило явно — через ADR.

## Решение

- Короткие формы создания/редактирования (ученик, урок, ДЗ, оплата, пакет) —
  **модалка** на базе `Dialog` (Radix), через единую обёртку `FormDialog`
  (`src/components/form-dialog.tsx`).
- Оверлей — `bg-background/80 backdrop-blur-sm` (следует теме: тёмный скрим в
  тёмной теме, светлый в светлой); закрытие по `Esc`, клику по фону и
  крестику; focus-trap и scroll-lock — из Radix. Контент скроллится на мобиле
  (`max-h-[90vh] overflow-y-auto`).
- Маршруты `/students/new` и `/students/[id]/edit` **удалены**; их заменяют
  `CreateStudentDialog` / `EditStudentDialog`. Server actions и редиректы не тронуты.
- Инлайн-формы со сворачиванием для создания **больше не используем**.
- `docs/DESIGN.md §6–§7` обновлены под это правило.

## Альтернативы

- **Оставить инлайн, починить тряску** (автоскролл/резерв высоты): не убирает
  разнобой с формой ученика и фундаментально всё равно двигает layout. Отклонено.
- **Гибрид** (часть форм — модалки, ученик — страница): меньше изменений, но
  сохраняет два паттерна и непоследовательность. Отклонено в пользу единообразия.
- **Bottom-sheet на мобиле**: лучше нативного ощущения, но лишняя сложность для MVP.
  Отложено — сейчас один адаптивный центрированный диалог.

## Последствия

- (+) Нет content-jumping; единый паттерн для всех пяти форм; фокус на действии;
  блюр/клик-мимо/Esc «из коробки».
- (−) Потеряли deep-link на `/students/new` и `/edit` (для MVP некритично).
- (−) Очень длинные формы в модалке неудобны — если появится мастер/большой профиль,
  он идёт отдельной страницей (см. §7 п.2).
- **Пересмотр:** если форма перестанет быть «короткой» (>6–7 полей, шаги) — выносим
  её на отдельный маршрут, не растягивая модалку.
