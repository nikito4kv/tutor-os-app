# ADR-0001: Стек и отказ от тяжёлого бэкенда

- **Статус:** принято
- **Дата:** 2026-06-10
- **Решают:** Tech Lead, команда

## Контекст

Цель — проверить гипотезу на живых репетиторах за **недели, а не месяцы**. Нужны
auth, БД, файлы, realtime и доступы «из коробки», минимум инфраструктурного кода.
Срок до первого теста — 1–2 недели.

## Решение

- **Фронт:** Next.js (App Router) + TypeScript strict + Tailwind + shadcn/ui;
  формы — React Hook Form + Zod.
- **Бэкенд/БД/Auth/Storage:** Supabase (Postgres + Auth + Storage) с RLS; серверная
  логика — Server Actions / route handlers Next.js.
- **Видео:** Daily.co (prebuilt). **Доска:** tldraw. **Email:** Resend. **Хостинг:** Vercel.
- **pnpm**; тесты — Vitest (юнит) + 1–2 Playwright e2e на главный сценарий.
- Качество: ESLint + Prettier + TS strict + husky/lint-staged.
- На этом этапе **сознательно НЕ берём** тяжёлый бэкенд: NestJS, Prisma, Redis, BullMQ.
- Механика «Завершить урок» — **синхронно**, функцией Postgres `complete_lesson`,
  без очередей и фоновых воркеров.
- UI по умолчанию русский, строки вынесены в словарь (`src/lib/i18n`) — задел на i18n.
- Деньги — **мультивалюта на репетитора** (поле `tutor.currency`, дефолт RUB),
  отображение только, без эквайринга.

## Альтернативы

- Отдельный NestJS/Prisma-бэкенд + своя auth + S3 + очереди — мощнее и гибче, но
  это недели инфраструктуры до первой проверки идеи. Отклонено для MVP.
- Свой WebRTC вместо Daily.co — огромная сложность, не профильная. Отклонено.

## Последствия

- (+) Быстрый сквозной цикл; меньше кода; auth/RLS/Storage/realtime бесплатно.
- (−) Часть логики живёт в БД (RLS, функции) — это надо уметь читать и тестировать.
- (−) Сложные фоновые цепочки придётся добавлять позже.
- **Пересмотр:** когда появятся тяжёлые фоновые процессы или мульти-тенант
  мини-школа — заводим новый ADR на миграцию (вероятно, выделенный бэкенд/очереди).
  Менять стек без нового ADR нельзя.
