# ROADMAP

MVP = учётное ядро (срезы 1–7) + опционально комната урока (срез 8). После того как
гипотеза подтверждена на живых репетиторах — двигаемся по этому порядку. Каждый
крупный шаг = отдельный билд; значимые решения фиксируем ADR.

## После MVP

1. **Комната урока** (если откладывали): Daily.co prebuilt + tldraw, вход по ссылке.
2. **CRM / воронка лидов** — учёт заявок и конверсии в учеников.
3. **Портал родителя** — отдельный доступ с прогрессом и оплатами.
4. **Аналитика** — дашборды: доход, отток, retention, загрузка расписания.
5. **AI-функции** — заметки/резюме урока, генерация ДЗ, подсказки.
6. **Мини-школа** — несколько преподавателей, роли, общий пул учеников.

## Параллельно (по мере спроса)

Онлайн-приём платежей + webhook · WhatsApp/Telegram-уведомления · библиотека
материалов · запись урока · повторяющиеся уроки и переносы · групповые пакеты ·
возвраты · внутренний чат.

Модель данных уже допускает эти расширения без переписывания ядра.

## Реализовано вне продуктового скоупа

- **Роль администратора (служебная)** — внутренний ops-аккаунт разработчиков:
  инбокс обратной связи + общие цифры (репетиторы/ученики/уроки/новые обращения).
  Это **не** «мини-школа» (продуктовые роли и общий пул учеников остаются в списке
  выше) и **не** продуктовая аналитика (доход/отток/retention — тоже остаётся).
  См. ADR-0003 и `docs/specs/admin-role/`. Денежные цифры на дашборде — позже.
